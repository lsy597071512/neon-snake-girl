## 3. P0 优化（私测期必做）

### 3.1 APK 体积治理 ⭐核心战场

#### 3.1.1 现状

- **APK 1.98 GB** → 普通用户首次安装 15-25 分钟；激活码后放弃率高
- 248 个 webm（角色立绘/互动/睡眠/调教）占大头
- 4 个 mp4（pv01, beijing01, shop, storyboards）约 60 MB
- 100+ 战斗 FBX + 13 GLB + 角色 emotion-poses PNG
- pv_720p.mp4 在 `dist/assets/` 和 `dist/tex/` **双份拷贝**（166 MB）⚠️

#### 3.1.2 已讨论方案对比

| 方案 | 减重 | 风险 | 推荐 |
|---|---|---|---|
| **A. webm VP9 → AV1** | -700 MB | 透明 alpha 兼容性；老设备硬解；编码慢 10-30× | ❌ 不推荐 |
| **B. AB 分包（assets 改 OBB）** | -800 MB ↑ | 上架合规；启动复杂度 | ⭐⭐⭐⭐⭐ |
| **C. webm 加载分层（按需云端）** | -150~300 MB | 需联网；离线场景崩 | ⭐⭐⭐ |
| **D. 同动作多 stem 合并** | -200 MB | 损失动效细节 | ⭐⭐⭐ |
| **E. BGM mp3 → 云端** | -18 MB | 首次启动需联网 | ⭐⭐⭐⭐ |
| **F. VP9 CRF 27 → 32** | -100 MB | 画质略降（肉眼难分辨） | ⭐⭐⭐⭐ |
| **G. 战斗 FBX 按需加载** | -100 MB | 战斗场景启动延迟 +200ms | ⭐⭐⭐ |
| **H. pv_720p.mp4 去重** | -166 MB | 容错处理 | ⭐⭐⭐⭐⭐（紧急）|

#### 3.1.3 推荐组合方案（可叠加）

| 阶段 | 动作 | 预期体积 | 工时 |
|---|---|---|---|
| **P0 周 1 紧急** | **H. pv_720p.mp4 去重**（build 流程修复）| -166 MB | 0.5 天 |
| **P0 周 1** | **B. AB 分包**：基础包 200 MB + OBB 1.6 GB | **200 MB** | 2-3 天 |
| **P0 周 2** | **E. BGM mp3 → 云端**（保留 2 首主旋律本地）| -16 MB | 0.5 天 |
| **P0 周 3** | **F. webm CRF 27→32**（仅战斗远景 webm）| -80 MB | 0.5 天 |
| **P1 月 1** | **C. 调教皮 webm 云端化** | -150 MB | 3 天 |
| **P1 月 2** | **G. 战斗 FBX 按关卡加载** | -100 MB | 2 天 |

#### 3.1.4 AB 分包详细方案

```
Android 项目结构（Capacitor）
├── android/
│   ├── app/build/outputs/apk/
│   │   ├── base-1.0.apk              (200 MB · 玩法必需)
│   │   └── main.1.com.neonsnake.obb  (1.6 GB · 高清资产)
│   └── ...

APK 内资产（200 MB）：
- 主程序 + HTML/CSS/JS（~30 MB）
- 战斗核心资源（~50 MB）
- 角色日常皮 + 战斗皮 webm（~80 MB）
- 1 张主旋律 BGM（~20 MB）
- 必要 PNG（~20 MB）

OBB 内资产（1.6 GB）：
- 调教皮 webm（13 角色 × 多套）
- 调情皮 webm
- 互动/睡眠 webm
- 4 个 mp4
- 其余 mp3
- 海报/剧情立绘
```

#### 3.1.5 不推荐的方向

- ❌ **VP9 → AV1**：透明 alpha + 老设备硬解风险太高，对私测不划算
- ❌ **webm VP9 → H.264**：VP9 在 Android 7+ 已普及，且 webm 容器对 alpha 友好

#### 3.1.6 验收

- APK ≤ 250 MB；OBB ≤ 1.8 GB
- 启动到战斗 ≤ 5 秒（基础包）
- OBB 解压到 `android/obb/<pkg>/` 自动挂载

### 3.2 私测门禁降耦

#### 3.2.1 现状

`src/main.ts` 第 84 行：
```ts
const licensed = await ensureLicensed();
if (!licensed) return;  // 阻断整个 App
```

**问题**：
- 网关故障 → 全游戏不可用
- 单点失败 → 无降级
- 调试期间反复激活码输入

#### 3.2.2 改造方案

| 改动 | 说明 |
|---|---|
| **A. 失败回退 localStorage 缓存** | 24h 内已成功激活 → 不再走网关 |
| **B. 网关超时 5s → 自动放行** | 信任模式（开发期可调）；私测仍以日志告警 |
| **C. 门禁 UI 化** | 不再阻塞 App 启动；失败时弹 licenseGate.ts 已有逻辑继续生效 |
| **D. 离线降级模式** | 私测激活用户在无网时仍可游戏 24h；超出则只读存档 |

#### 3.2.3 推荐实施

```ts
// src/platform/license.ts 重构示意
async function ensureLicensed(): Promise<boolean> {
  // 1. 本地缓存优先
  if (licenseCache.validUntil > Date.now()) return true;
  
  // 2. 网关带超时
  try {
    const ok = await Promise.race([
      fetchGatewayLicense(),
      timeoutAfter(5000, () => 'timeout'),
    ]);
    if (ok === 'timeout') return licenseCache.allowOffline;
    return ok;
  } catch {
    return licenseCache.allowOffline;
  }
}
```

#### 3.2.4 验收

- 网关故障时已激活用户仍可游戏
- 失败有埋点上报
- 私测激活码与开发态分流开关保留

### 3.3 AI 生活引擎性能

#### 3.3.1 现状

`src/ai/heartbeat.ts`（已有 8 分钟心跳）+ `characterPersona.ts`：
- 13 角色并发漂移 + dayMode 重算
- 加上 LLM 缓存命中 / 失败回退，老设备 CPU 单核长期 30-50%

#### 3.3.2 优化方案

| 优化 | 实施 | 预期收益 |
|---|---|---|
| **A. 心跳分桶** | 13 角色分 13 个时间槽，每 8 分钟轮一次 | CPU 占用 -85% |
| **B. LLM 响应复用（模板缓存）** | 相同 prompt 命中 → 30 天内不复调 LLM | LLM 费用 -60% |
| **C. dayMode 重算懒化** | 仅当角色进入对话/事件触发时重算 | 心跳计算 -50% |
| **D. 后台心跳暂停** | App 退后台时停 `heartbeat.tick()` | 后台耗电 -90% |
| **E. 角色分组唤醒** | 玩家当前关注的角色 + 同房间角色高频；其他低频 | 高频响应零变化，低频 -70% |

#### 3.3.3 推荐组合 A + B + D（成本最低、收益最大）

- A：1 天实现
- B：复用现有 `llmRouter.ts` 缓存层
- D：`CapApp.addListener('appStateChange', ...)` 已在 main.ts；扩展即可

#### 3.3.4 验收

- 待机（13 角色在线）CPU ≤ 5%
- 单角色对话响应 ≤ 1.5s（P50）
- LLM 月费 -50% 以上

### 3.5 角色 alpha 兼容性

#### 3.5.1 现状

- 透明 webm 在某些骁龙 845 / 联发科 Helio G80 上**黑底/绿底显示**
- 用户反馈集中在淘宝/抖音买的中低端机

#### 3.5.2 方案

| 方案 | 实施 | 兼容性 |
|---|---|---|
| **A. webm 编码参数调整** | VP9 + yuva420p + libvpx-vp9 + 2-pass | 90% 兼容 |
| **B. webm alpha 兜底 PNG 序列** | 5 张关键帧 PNG 替代 webm（仅封面 + 互动节拍）| 100% 兼容 |
| **C. 首帧 poster + webm 双轨** | 显示时优先 poster，等待 webm 加载完成 | 解决黑闪 |
| **D. 强制启用 WebView 硬件加速** | `android:hardwareAccelerated="true"` + manifest 配置 | 80% 兼容 |

#### 3.5.3 推荐 A + C + D

- A：build-ship 加 `--alpha-mode=1 --passes=2`
- C：ship manifest 加 `webm.poster` 字段
- D：capacitor.config.ts 加 `webContentsDebuggingEnabled`

#### 3.5.4 验收

- 5 台覆盖机型（骁龙 845/870/8Gen2 + Helio G80 + 天玑 9000）全通过
- alpha 显示正确率 ≥ 95%

## 9. 风险与权衡

### 9.1 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 私测用户对体积敏感 | 中 | 私测期告知+OBB 自动下载 |
| 调教/小黑屋合规风险 | **高** | iOS 关闭 + Web PWA 兜底 |
| LLM 服务稳定性 | 中 | 多模型路由 + 缓存 |
| 私测激活码被滥用 | 低 | 设备绑定 + 异常检测 |
| 大量 webm 资产版权 | 中 | 内部 AI 流水线；不依赖外部 |
| i18n 迁移工作量大 | 中 | 渐进式抽取；先英/日 |
| iOS 审核失败 | 中 | 双轨（PWA 兜底）|

### 9.2 权衡原则

- **体积 vs 画质**：私测期画质优先（已通过 P2 v3.1 保护）；正式上线后云端化
- **变现 vs 体验**：月卡 + 战令 温和档；不引入 PVP 付费
- **自动化 vs 人力**：私测期人工校验优先；规模化后 CI
- **跨平台 vs 调教**：iOS 关闭调教，保 PC + Android 完整版
- **测试 vs 进度**：核心模块先覆盖，新功能随 PR 即测
