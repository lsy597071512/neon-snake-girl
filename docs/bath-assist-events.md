# 硬性玩法事件 · 现实逻辑规范（浴室 / 安抚 / 舞蹈 / 调教）

> 上级纲领：**[ai-first-principle.md](./ai-first-principle.md)**（第一宗旨 · 活人定律）。
> 本文只规定"硬性事件如何保持活人内核"，冲突时以纲领为准。
> 涉及代码：`bathAssistSession.ts` / `anfuSession.ts` / `danceSession.ts` / `disciplineSession.ts` / `outfitChangeProcess.ts` / `sleepSystem.ts`

---

## 1. 为什么需要这份规范

这些事件有按钮、相位、专属美术与 BGM（**玩法外壳是确定的**），但它们仍然是"角色在现实里做的事"（**内核必须真实**）。
外壳的确定性不能成为把角色写成开关的理由。

---

## 2. 四事件共同硬约束

| 约束 | 落地要求 |
|---|---|
| 进入要够得着 | 在睡觉/别的事件里 → 必须被叫醒且**叫得醒**，或角色同意；不允许瞬移/瞬醒/瞬换皮 |
| 允许拒绝 | 拒绝是正常结果；拒绝理由来自性格、好感、疲惫、正在做的事 |
| 相位真实 | 换装中只能说在换、待机只能说还没开始、进行中才能说正在做、被打扰只能梦呓或恼火 |
| 独占 | 同一角色同一时刻只在一个事件里；互斥事件之间显式拒绝并说明"等这边结束" |
| 过程与散场 | 进场有换装/移动过程；结束要换回日常、离开场地、恢复自主（不许一清了之） |
| 代价 | 打扰睡眠、中途离开、放鸽子、强行叫醒都要有状态/好感后果 |
| 可恢复 | 读档、切人、关对话、异常退出都必须能恢复；禁止不可逆锁 |

## 3. 逐事件要点

### 3.1 浴室（bathAssist）
- 进入前必须清醒（睡眠中必须先叫醒且叫得醒）；深度睡眠叫不醒＝进不去。
- 洗浴过程皮/毛巾是过程态，不是"换装"结果；不要把过程皮当日常。
- 淋浴/入浴是"独占地点"，其它事件必须拒绝。
- 结束后必须换回日常并离开浴室（散场），不得停在毛巾态。

### 3.2 安抚室（anfu）
- 睡眠中答应去安抚室 → 先按睡眠唤醒难度判定；叫不醒则拒绝。
- 待机/安抚中/疲惫是三种不同相位，Prompt 与立绘必须一致。
- 安抚中被打断：好感按打扰程度扣；安抚满足后的疲惫睡眠再被打扰，记忆权重更高。
- 离场（关页/结束）要结算并散场，不允许"安抚中"状态残留。

### 3.3 舞蹈（dance）
- 先换舞装（过程皮）→ 待机 → 真正起舞；音乐只在"正视起舞"时播放。
- 停下（stop）＝回待机、事件继续；结束（end）＝换下舞装、离开大厅、事件结束。两者语义不得混用。
- 独舞/共舞切换是同一套舞装的动作切换，不是换衣。
- 结束时若仍在舞蹈场地，应回到来处；已自行离开则不再搬动。

### 3.4 调教（discipline）
- 与其它事件互斥；进入前必须清醒且同意。
- 阶段推进要有过程与状态后果，不得跳过阶段直接给结果。
- 结束必须散场并清理临时皮/位置，避免"负一层卡死"。

## 4. 已知问题状态（2026-10-21 更新）

### 已修复（详见 [ai-realism-audit.md](./ai-realism-audit.md)）

1. **营地群体事件临时外覆**：改为换装过程队列（先换衣后显形），事件结束取消队列并排一次"换回日常"。
2. **出征清临时外覆**：清皮后排队一次换装过程，不再瞬时剥皮。
3. **浴室淋浴/泡澡/帮洗准备**：进浴、离浴、帮洗 prepare 全部走临时皮换装队列。
4. **舞蹈待机 → 起舞**：新增 `unveil`（换演出服）2.4s 过渡，BGM 仍以真正起舞为准。
5. **同屏统一外覆**：同屏成员也走换装队列；睡太沉叫不醒者不参与同屏。
6. **睡眠中进入事件**：舞蹈/安抚/浴室均按唤醒难度判定，叫不醒就拒绝；事件中也不能被"睡吧"打断。

### 仍待处理 / 已按设计决定

- ✅ 事件入口与散场的**瞬移**：已改为 `travel.ts` 行程（走路有耗时，途中不切场景/不落点）。

- ⏸ 安抚阶段皮瞬时切换：**设计决定**保留（现有相位/过渡足够）。

- 剩余模拟粒度：走路只有耗时、无逐房间路径；离线不自发产生营地事件（摘要会诚实说明）。
