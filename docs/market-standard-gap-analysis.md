> 视角:游戏研发 / 技术 / 代码 / 玩法 / AI

## 一、现状总览:功能上"意外地强",定位上"单机原型"

先给结论:**技术完成度已接近"可发行的独立游戏",但体感停在"内部测试包"。** 核心矛盾是——AI 生活模拟这块(13 人营地、四层记忆、人格漂移、NPC 互聊、TTS/ASR)做得比市面上 90% 的商业 AI 陪伴产品还深,但**战斗/养成/数值是极简占位**,而玩家每天花最多时间的恰恰是战斗与养成循环。情感投入(AI)与成长投入(战斗)两条线**没有互相兑现**,导致两边都弱。

- 13 角色 / 20 武器 / 40 关(程序生成,非手编)/ 6 成就
- 战斗:Three.js 3D(`Combat3D.ts` 1600 行)、三车道、数字门、打桶、Boss、TCP 战力判定
- 营地:2D UI + 纯文字日志;**角色没有可见的"身体在场"**(无 3D 漫步、无表情切换、无空间感)

## 二、技术层:离"市场标准"缺 6 块硬基建

| 缺口 | 现状 | 市场标准 |
|---|---|---|
| **包体治理** | `dist/` ≈ **2GB**;`pv_720p.mp4` 在 `dist/assets/` 和 `dist/tex/` **双份拷贝**(166MB);Debug APK 已 339MB | 手游安装包 <200MB(常见 80~150MB),资源 webp/avif + 纹理图集 + **asset-pack/OBB 分包或云加载** |
| **资源管线** | tex 全量复制,无哈希/压缩/懒加载 | 按需懒加载 + CDN + 分级画质(已有 `combatQuality` 雏形,可扩展) |
| **监控/埋点** | 无 Sentry、无 analytics,`catch{}` 静默吞错 100+ 处 | 崩溃上报 + 关键漏斗埋点(关卡流失/付费转化) |
| **工程设施** | 无单元测试、无 CI、无 eslint/prettier;`verify-*` 是手动冒烟脚本 | vitest + GitHub Actions + 提交即校验 |
| **商业就绪** | AdMob 是 Google **测试 ID**;无 IAP;release 未签名未混淆 | 正式广告位 + 内购 + 签名/proguard + 合规 |
| **安全** | `allowMixedContent: true`(为局域网 TTS 妥协)、LLM Key 打进 bundle | 走服务端代理网关,不信任客户端 |

**架构优点(值得保留,不用推翻):**

- `platform/` 隔离 Capacitor,`voice/` 三态降级(原生插件 → HTTP 代理 → 系统 TTS)
- 语音会话代数(generation)防竞态、错误码中文化、12s 录音上限
- `VfxPool` 对象池、三档画质 profile、`webglCaps` 探测
- BGM 管理器:5 轨独立淡入淡出世代号 + 全局 duck(为语音让路)

## 三、代码层:可维护性的 3 个债

1. **`App.ts`(100KB)上帝文件** + `ai/` 40+ 文件高耦合互引 —— 建议按"对话域/营地域/皮肤域"拆模块,补类型层面的事件总线。
2. **零测试**。`dialogueEngine` / `memory` 这类核心一旦回归,全靠肉眼;至少给 `formulas.ts`、`SaveManager`、`memory` 的分槽/召回逻辑写单测。
3. **文案硬编码中文、无 i18n** —— 若想进海外(市场翻倍),这是起步价。

## 四、玩法层:为什么"好玩"撑不住

**Core loop**:过关 → 金币 → 抽卡/军械箱 → 战力 → 卡关。问题:

1. **40 关是公式堆的**(`stages.ts` 里 timer/waves/enemyHp 全是 `combatParams(n)` 算出来的)。没有手编关卡、没有机制增量(第 20 关和第 5 关除了数值没区别)→ 中期就腻。市场标准是**每章引入一个新机制词条**(轨道机关、护盾类敌人、追逐关、Boss 三阶段)。
2. **自动战斗第 8 关解锁** = 亲手玩的激励在第 8 关就断了;手动仅多 0.82→0.95 胜率,**操作无成长**(无技能树、无走位收益、无连段反馈)。打击反馈只有合成音 + bloom,**没有战斗 SFX 采样、没有震屏、没有连击结算爽点**。
3. **养成维度单一**:武器 = 唯一战力来源,角色稀有度定基础值 → 抽到角色后只剩"数值堆"。无装备词条、无配队 synergy、无技能搭配。市场的"养"是**决策树**,这是**线性增长**。
4. **情感与战力脱钩**:好感度升到"信赖"不影响战斗(不出场 buff、无专属剧情解锁关卡)——玩家会问"我养她干嘛"。这是两条主线最大的断层。
5. **6 个成就、无活动、无排行、无社交** —— LiveOps 为 0。

## 五、AI 层:为什么"感情/沉浸/自我意识"感觉弱(核心问题)

先说清楚:**AI 机制层一点都不弱**——四层记忆(`memory.ts`)、人格漂移与今日模式(`characterPersona.ts`)、好感+角色间关系(`relationship.ts`)、欲望/议程/人生时间线、营地事件、NPC 互聊、TTS 情绪韵律、ASR。**弱在"玩家能感知到的呈现通道"和"连续性的自我"上**,即:机制强、可感知性弱。具体 8 条:

### A. 情感被"说出来"但没被"演出来"(最大短板)
- `emotion` 是**每句一个标签**(neutral/happy/...),不驱动任何可见变化:**立绘不换表情、不换姿势、不换光、BGM 不变、气泡不出动作**。情感只落在文字上——而文字是最廉价的表达通道。
- 市场标准的"感情" = **Live2D/3D 角色情绪状态机**:眼睛、嘴角、呼吸、脸红、朝向;好感阶段性"解锁新表情/新语气/新称呼"。已有 webm 动态立绘,但**没有按 emotion 切换的情绪驱动层**。

### B. "自我意识"是被 Prompt 拼出来的,不是角色自洽的
- 每次对话,角色的人设都是 `promptAssembler` **现拼的**(世界观+快照+欲望+今日模式+场景卡)。模型确实读了,但**没有一个持续存在的"自我"对象**——它无法回答"我到底是谁、我此刻在开心什么、我为什么对你特别"。
- 建议加一个**"关系弧线"(relationship arc)状态机**:初见→陌生→熟悉→信赖→亲密,每个阶段有专属称呼、专属话题、专属约定与纪念记忆;重大节点(第一次送礼、第一次牵手、第一次吵架)作为**里程碑记忆**强约束注入,让角色"真的记得"并主动提及。

### C. 情绪没有"连续体",只有"单点标签"
- 情绪无衰减曲线、无历史序列、无 mood 量表可见化。玩家无法感知"她今天比昨天开心/低落"。
- 建议:情绪 = **状态机 + 衰减 + 事件驱动**,且把 mood 在营地 UI 上做成**可见的心跳/光效/语音语气**,让"情绪"成为可观察的活参数。

### D. 主动性的密度太低
- `heartbeat.ts` 至少 8 分钟一次稀疏事件;角色大部分时间**不存在**。市场标准是角色有自己的**可见日程表**(几点在餐厅、几点回房),并且**会主动找你**(想你/好奇你在干嘛/吃醋),而不是等你点开对话框。
- 已有 `playerOutreach` / `npcOutreach` / `companionFollow`,方向对了,但要把它们**挂到可见日程与物理移动**上。

### E. 缺乏"多模态在场感"
- 角色看不到你、听不到环境;一切是文本快照。ASR+TTS 已通,但**没有"语音→角色反应"的实时回路**(你说"你怎么了",她表情立刻变)——这是现在 AI 陪伴类的核心卖点,你有全部底层件,只差一根"ASR 结果→情绪驱动→立绘/语气"的连线。

### F. 情感兑现不足(与玩法断层呼应)
- `affinity` 目前只影响文案,不影响:战斗出场加成、专属剧情、皮肤折扣、对话自由度。**让好感真正解锁内容**,AI 才会被玩家当回事。

### G. 生成体验细节:延迟与一致性
- 实测 GPT 路径 7~9s,且**无流式输出**——等待期=出戏期。建议:Qwen 主路 + **SSE 流式** + 等待期 TTS 口癖/小动作;继续压模板化傲娇(已有 `looksLikeGenericTsundere` 重试,说明痛点已知)。

### H. 记忆一致性
- 关键词召回 + 分槽保护已很好,但模型仍会"昨天答应今天忘"。建议把**承诺/约定/名字/称呼**做成**结构化事实表**(独立于自由文本记忆),每次对话**校验并强制注入**,这是"自我意识感"最便宜的来源。

## 七、优先级路线图(按"感知提升/投入产出比"排序)

**P0 · 把 AI 从"能聊"变成"能感觉到活着"(1~2 周)**

1. 情绪驱动可见通道:emotion → 立绘表情/姿势/光/BGM 联动(已有 webm 与 bgm ducking 基建,接线即可)
2. ASR 结果 → 实时情绪反应回路(把已有 ASR/TTS/emotionProsody 串成闭环)
3. 关系弧线状态机 + 结构化事实表(承诺/名字/约定强约束注入)
4. 流式输出,砍到 2~3s 内

**P1 · 让情感兑现成玩法(2~3 周)**

5. 好感度 → 战斗加成/专属剧情/出场语音的门槛系统
6. 角色"可见日程 + 主动找你"(把 heartbeat 密度提上来,挂到营地空间表现)

**P2 · 市场标准的"好玩"(中期)**

7. 战斗:震屏/命中停顿/SFX 采样 + 每章 1 个新机制 + 手动操作成长(技能/连段)
8. 养成:武器词条 + 配队 synergy,替代纯战力堆叠
9. 包体治理:OBB 分包或云资源,目标 APK <150MB
10. 工程:单测 + CI + Sentry + 埋点 + AdMob 正式位 + IAP + 签名混淆

---

**一句话总结**:AI 是"**机制上的巨人、呈现上的侏儒**"——把感情从文字里搬到表情、声音、日程、身体上去,并让好感真正改变玩法,产品的"活着感"立刻质变;玩法的下一步不是加关,是**加机制与手操深度**,否则玩家在第 8 关自动战斗后就只剩"看文字"了。
