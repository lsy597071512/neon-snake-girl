## 1. 系统目标与核心原则

| 目标 | 实现手段 |
|---|---|
| 私测发行：一人一号，APK 被转发无法使用 | 兑换码/订单号 → 设备绑定（Android ID）→ HMAC token |
| 玩家侧零门槛 | 首屏只填「兑换码（或订单号）+ 自己的千问 API Key」两栏 |
| 开发者零服务器成本 | Cloudflare Workers + D1 免费档（10 万请求/天） |
| 开发者零 AI 成本 | **BYOK**：AI 调用用玩家自己的 DashScope Key，直连阿里云，**不经过网关** |
| 防 API Key 泄露 | 构建产物内**不含任何开发者密钥**（.env.local 已清空，key 只存玩家手机本地） |
| 国内可直连 | 网关绑定自有域名 `license.youziligames.com`（workers.dev 默认域名在大陆被阻断） |

**核心认知：网关只管「身份」，不管「AI 流量」。** AI 对话是玩家手机 → 阿里云 DashScope 直连。因此即使网关宕机，已登录玩家（token 未过期）的 AI 功能不受影响。

## 2. 架构总览

```
┌───────────── 玩家手机（APK）─────────────┐
│                                          │
│  main.ts                                 │
│    └─ ensureLicensed()                   │
│        ├─ 无 token → loginGate 登录界面   │
│        │    输入: 兑换码/订单号 + 千问Key  │
│        │    ├─ POST /api/login ──────────┼──→ Cloudflare Worker
│        │    └─ 千问Key 实连校验 ──────────┼──→ DashScope（直连）
│        └─ 有 token → 进入游戏             │
│                                          │
│  AI 对话: 玩家Key ───────────────────────┼──→ DashScope（直连，不过网关）
│  TTS/ASR: 同上（同一把 Key）              │
└──────────────────────────────────────────┘
                    │ token（HMAC 签名，30 天）
                    ▼
         Cloudflare Worker（rust-belt-license）
                    │
                    ▼
              D1 数据库（codes + devices 表）
```

### 3.4 密钥与配置存放

| 密钥 | 存放位置 | 用途 | ⚠️ |
|---|---|---|---|
| `LICENSE_SECRET` | CF Worker 环境变量（`wrangler secret put`） | HMAC 签名 token | 泄露=可伪造许可 |
| `ADMIN_KEY` | CF Worker 环境变量 + `gateway/.secrets.local.json`（本地副本） | 管理接口鉴权 | 泄露=可随意发码 |
| `AFDIAN_TOKEN` / `AFDIAN_USER_ID` | CF Worker 环境变量（**可选，未配置则订单号登录不可用**） | 爱发电订单验证 | — |
| 玩家千问 Key | 玩家手机 localStorage（`rust-belt-ai-api-key`） | AI 功能 | 只存玩家本地 |

`gateway/.secrets.local.json` 记录 `{LICENSE_SECRET, ADMIN_KEY, url}`，**已被 .gitignore，绝不外传**。所有管理命令自动读取它。

## 4. 数据模型（D1）

```sql
codes(                                  -- 许可主表（兑换码 或 爱发电订单）
  code TEXT PRIMARY KEY,                -- 'RB-XXXX-XXXX' 或 'afdian:<订单号>'
  note TEXT,                            -- 备注（批次/来源）
  max_devices INTEGER DEFAULT 3,        -- 设备数上限
  revoked INTEGER DEFAULT 0,            -- 1=已停用
  last_self_unbind_at INTEGER DEFAULT 0,# 玩家自助换绑冷却（30 天一次）
  created_at INTEGER
)
devices(                                -- 设备绑定
  code TEXT, device_id TEXT,            -- 联合主键
  device_name TEXT, activated_at INTEGER, last_seen INTEGER
)
```

- 兑换码格式：`RB-` + 两段 4 位（字符集去掉 0/O/1/I），生成于 `genCode()`
- 爱发电订单许可：code = `'afdian:' + 订单号`，首次订单号登录时自动 INSERT（幂等）

## 5. Token 规格

```
token = base64url(JSON payload) + '.' + base64url(HMAC_SHA256(payload, LICENSE_SECRET))
payload = { c: 许可标识, d: 设备ID, exp: 过期秒级时间戳, iat: 签发时间 }
TTL = 30 天
```

- **客户端不持有密钥 → 无法本地验签、无法伪造续期**。本地只检查 exp 是否过期
- 服务端校验：签名 → exp → code 是否 revoked → 设备是否仍绑定，全部通过才返回 ok
- 吊销/解绑的生效路径：玩家客户端每 24h 在线调 `/api/validate`，被拒则清除本地 token → 回登录界面

## 6. 核心流程

### 6.1 首次登录（玩家）

```
首屏 loginGate（兑换码/订单号 + 千问Key 两栏）
 1. POST /api/login {code|account, deviceId, deviceName}
    ├─ 纯数字≥12位 → 爱发电订单流程：
    │    Worker 调 afdian open API 验证订单真实且已支付
    │    → 自动 INSERT codes('afdian:<单号>')（幂等，免人工开户）
    │    → 未配置 AFDIAN_* 密钥时返回 ORDER_NOT_FOUND
    ├─ 否则按兑换码查 codes 表
    ├─ 设备数检查：未绑定且已满 → 403 TOO_MANY_DEVICES（客户端显示自助换绑按钮）
    └─ 通过 → 绑定设备 + 签发 token
 2. setStoredApiKey(千问Key)（存玩家本地）
 3. 实连校验 Key（qwen-flash 1 token 微调用）→ 坏 Key 当场报错
 4. 进入游戏
```

### 6.2 日常启动（已登录）

```
main.ts → ensureLicensed()
  ├─ token 本地未过期 → 放行
  │    └─ 距上次在线校验 >24h 且在线 → 静默 /api/validate（失败=断网宽限，不清 token）
  └─ 无/过期 token → loginGate
```

### 6.3 换设备

- 玩家自助：登录界面「强制解绑旧设备」→ POST /api/self-unbind {code} → 清空该码全部设备（30 天冷却，服务端强制）
- 开发者手动：`node scripts\manage-codes.mjs --unbind <码>`（不受冷却限制）

### 6.4 爱发电订单号登录（自动发货卖法）

```
你：爱发电上架商品（自动回复写"用你的订单号登录"）→ 零发货操作
玩家：付款 → 订单页复制订单号 → 游戏输入 订单号+Key → Worker 验单 → 自动开通
```

需在 Worker 配置 `AFDIAN_TOKEN` + `AFDIAN_USER_ID`（爱发电开发者设置获取），配置命令：
`npx wrangler secret put AFDIAN_TOKEN` / `AFDIAN_USER_ID`（在 gateway 目录）。

## 8. 网关 API 明细（`gateway/worker.js`）

| 端点 | 方法 | 鉴权 | 说明 |
|---|---|---|---|
| `/api/ping` | GET | 无 | 存活探针 |
| `/api/login` | POST | 无（需有效码/订单号） | 登录+设备绑定 → token。错误码：INVALID_CODE / CODE_NOT_FOUND / CODE_REVOKED / TOO_MANY_DEVICES / ORDER_NOT_FOUND（未配 afdian 或订单无效） |
| `/api/validate` | POST | 无（需 token） | 校验 → {ok,code,exp}；401=TOKEN_INVALID_OR_EXPIRED / CODE_REVOKED / DEVICE_UNBOUND |
| `/api/self-unbind` | POST | 无（需码） | 自助换绑，30 天冷却（COOLDOWN + retryAfterDays） |
| `/api/admin/players`·`codes` | POST/GET | X-Admin-Key | 开户/发码/列表 |
| `/api/admin/revoke` | POST | X-Admin-Key | 停用 |
| `/api/admin/unbind` | POST | X-Admin-Key | 强制解绑（无冷却） |

> 注：历史命名残留——管理端玩家接口路径为 `/api/admin/players`（v2 账号制遗留），当前码池模式实际使用 `/api/admin/codes` 系列。

## 11. 已知限制与风险

1. **token 无法本地验签**：密钥不能下发客户端。断网 30 天后 token 过期必须联网重登（AI 本身需联网，可接受）
2. **Android ID 可被重置**（刷机/部分清除数据）→ 占用新设备位，需手动解绑
3. **APK 可被重打包**（无签名校验），但无有效码/订单无法登录 → 商业闭环不受影响
4. **workers.dev 在大陆被阻断** → 已用自有域名解决；若自有域名也被墙，需换 CN 厂商（EdgeOne 等，Worker 代码基本可平移）
5. **爱发电订单号登录依赖 afdian 服务可用性**；afdan 审核策略变化可能影响 open API
