## 三、启动后端（二选一）

### 方案 A：llama.cpp（推荐，MTP 加速支持最好）

```bash
./start-llamacpp.sh ./models/你的模型.Q5_K_M.gguf
```

关键参数说明：

- `-c 65536` 上下文 64K（24G 卡的甜点值；要更长就把 KV 量化开满）
- `-ngl 99` 全部层上 GPU
- `-fa` 闪存注意力，必开
- `--cache-type-k q8_0 --cache-type-v q8_0` KV 缓存 8bit 量化，显存减半且几乎无损

### 方案 B：KoboldCpp（单文件，开箱即用）

```bash
./start-koboldcpp.sh ./models/你的模型.Q5_K_M.gguf
```

### MTP 投机解码（可选，提速 20-40%）

llama.cpp 支持用小模型做 draft model，若仓库提供了 MTP 文件：

```bash
-m 主模型.gguf -md MTP模型.gguf -ngl 99 -c 65536 -fa
```

> 不同 llama.cpp 版本的 MTP 参数名有差异（`-md` / `--model-draft` / `--draft-max`），
> 以你本机 `llama-server --help` 输出为准。

## 四、SillyTavern 配置

### 1. 连接后端

| 项 | 值 |
|---|---|
| API | `Chat Completion` |
| 聊天补全来源 | `llama.cpp server` 或 `KoboldCpp` |
| Base URL | `http://127.0.0.1:8080/v1`（llama.cpp）/ `http://127.0.0.1:5001/v1`（KoboldCpp） |
| 上下文模板 | **ChatML**（Qwen 系原生模板） |
| 指令模式 | 关闭（ChatML 已含角色结构），或按作者 README 指定 |

### 2. 导入采样预设

把 `sillytavern-preset-qwen38-fable.json` 放进
`SillyTavern/default/settings/presets/`，在预设面板选择导入。

核心参数（可微调）：

| 参数 | 值 | 理由 |
|---|---|---|
| Temperature | **1.0** | 情感多样性，低于 0.85 会变模板腔 |
| Min P | **0.05** | 比 top_p 更适合长篇 RP，过滤劣质尾部 |
| Top P | 0.95 | |
| Top K | 0（关） | 交给 Min P |
| **Smoothing Factor** | **1.5** | **作者官方建议**（对话/RP场景），KoboldCpp/ST/text-generation-webui 均支持 |
| Repetition Penalty | **1.05** | 若后端不支持 smoothing，替代方案是提到 1.1~1.15 |
| Presence / Frequency Penalty | **0** | 本地模型叠加这两个容易出怪句 |
| Max Tokens | 400~600 | 长回复可到 800 |

### 3. 思考模式（关键）

TURBO 版本已把思考 token 压到 1/2~1/10，所以**保留思考模式** ——
模型的 thinking 块天然就是"角色内心戏"，正好满足你要的"自我思考/自主决策"。

- 想让内心戏参与叙事：思考完成后直接输出，把 `[thinking]` 前缀剥掉即可
- 想要秒回：在 ST 的 API 参数里加 `{"chat_template_kwargs": {"enable_thinking": false}}`
- **思考档位**：由 Jinja 模板控制，默认 `xhigh`。在模板顶部改 `reasoning_effort` 为 `medium` 或 `low`；medium 档会关闭系统提示注入，允许你自己塞推理专用提示
- **TURBO 副作用**：对提示词更敏感 —— 想让思考块更短更稳，就把角色卡/指令写得**更细**，别让模型猜；多轮对话中后续轮次的思考压缩会更明显

### 4. 敏感内容的重要提示

Heretic 祛审查 ≠ 自动放开尺度。该模型**默认输出偏"温和"**：
想生成露骨、激烈或粗口内容，需要在角色卡 / system 提示里**主动指定尺度和用词**，
否则成品会偏平淡。这是作者明确提示的行为特征，不是模型缺陷。

### 5. 长对话设置

- 上下文长度填 **65536**（与后端一致）
- 开启 ST 的 **故事摘要/记忆**，但把摘要触发阈值设在 40K 之后 —— 本地 262K 底座很能装，过早摘要反而丢失伏笔

用你最熟的一张角色卡，跑满 50 楼后逐项打分（1~5）：

| # | 检查项 | 得分 |
|---|---|---|
| 1 | 人设是否漂移（口癖/身份/关系是否走样） | |

总分 ≥ 32 分 → 稳妥主力；< 24 分 → 换 Q5_K_M 或切回 Qwen3.5-27B abliterated 对照。

## 六、常见问题

| 症状 | 原因 / 解法 |
|---|---|
| 爆显存 | 换 Q4_K_M；确认 KV 量化参数生效；上下文降到 48K |
| 中文夹英文 | 在角色卡和 system 里明确"仅用简体中文输出" |
| 文笔过于浓烈/爱用 emoji | DavidAU 融合模型的自带性格，在 system 提示里压制："文风克制，禁止使用 emoji" |
| 回复啰嗦重复 | 先确认 smoothing_factor=1.5 已生效；再考虑 Min P 提到 0.06 |
| 敏感内容太"温" | 不是审查残留——在角色卡里主动写明尺度和用词，模型默认风格偏含蓄 |
| MTP 反而变慢 | token 接受率 <50% 时普通版更快，换普通量化文件 |
| 速度为 0 / 卡顿 | 检查是否误开了 thinking 全量输出；或模型被部分卸载到内存（看启动日志的 offload 行数） |

## 附录 A：start-llamacpp.sh

```bash
#!/usr/bin/env bash
# ============================================================
# llama.cpp 启动脚本 — Qwen3.8-27B Fable-Fusion Heretic（24GB 显存）
# 用法: ./start-llamacpp.sh /path/to/model.Q5_K_M.gguf
# ============================================================
set -euo pipefail

MODEL="${1:?请传入 GGUF 模型路径，例如 ./models/qwen3.8-27b-fable.Q5_K_M.gguf}"

# ---------- 可调参数 ----------
CONTEXT=65536        # 上下文：24G 卡甜点值；想更长改 98304 并把 KV 量化开满
GPULAYERS=99         # 全部层上 GPU
PORT=8080
THREADS=$(nproc)

# MTP 投机解码（可选）：若仓库提供了 MTP 小模型，填入路径即可提速 20-40%
MTP_MODEL=""         # 例: "./models/qwen3.8-27b-mtp.gguf"

# ---------- 组装命令 ----------
CMD=(
  llama-server
  -m "$MODEL"
  -c "$CONTEXT"
  -ngl "$GPULAYERS"
  -t "$THREADS"
  -fa                              # Flash Attention，必开
  --cache-type-k q8_0              # KV 缓存 8bit 量化，显存减半且几乎无损
  --cache-type-v q8_0
  --host 127.0.0.1
  --port "$PORT"
)

# 投机解码（如已提供 MTP 模型）
if [[ -n "$MTP_MODEL" && -f "$MTP_MODEL" ]]; then
  CMD+=( -md "$MTP_MODEL" -ngl 99 )
fi

echo "==> 启动 llama.cpp server"
echo "==> 模型: $MODEL"
echo "==> 上下文: $CONTEXT  端口: $PORT"
echo "==> 完整命令: ${CMD[*]}"
echo

exec "${CMD[@]}"
```

## 附录 B：start-koboldcpp.sh

```bash
#!/usr/bin/env bash
# ============================================================
# KoboldCpp 启动脚本 — Qwen3.8-27B Fable-Fusion Heretic（24GB 显存）
# 用法: ./start-koboldcpp.sh /path/to/model.Q5_K_M.gguf
# 备选后端：单文件、无需编译，适合不想折腾的环境
# ============================================================
set -euo pipefail

MODEL="${1:?请传入 GGUF 模型路径}"

CONTEXT=65536        # 上下文
GPULAYERS=99         # 全部层上 GPU
PORT=5001
THREADS=$(nproc)

echo "==> 启动 KoboldCpp (API 模式)"
echo "==> 模型: $MODEL"
echo "==> 上下文: $CONTEXT  端口: $PORT"

exec python3 koboldcpp.py \
  --model "$MODEL" \
  --gpulayers "$GPULAYERS" \
  --contextsize "$CONTEXT" \
  --threads "$THREADS" \
  --flashattention \
  --usecublas \
  --mmap \
  --quantkv 1 \
  --port "$PORT" \
  --api

# 说明：
#   --quantkv 1  : KV 缓存量化，显著降低长上下文显存占用
#                  （不同版本取值含义不同，0=关闭/1=Q8 居多，以 --help 为准）
#   --api        : 只开 API 服务，SillyTavern 走 Chat Completion → KoboldCpp
#   --flashattention : 必开，长上下文提速明显
```
