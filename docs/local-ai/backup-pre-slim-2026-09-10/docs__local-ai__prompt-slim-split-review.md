# Prompt 拆分 / 瘦身：好处·风险·硬规则·13 人深挖

> **本文只分析，不改代码。**  
> **硬规则（写死，后续一切优化必须服从）**：  
> 1. **一比一等价**：瘦身后模型应遵守的约束集合 = 瘦身前；不许靠「少说两句规矩」换速度。  
> 2. **不得影响角色本人**：声线 / 正反例 / 禁止 / 好感区间 / 成人表达 / 档案事实 / 秘密 一律不得删减语义。  
> 3. **不得影响玩法**：换装时序、嘴腿同步、洗浴同意、小黑屋、经济/义体、世界意图切景、JSON 字段契约、话题收束等玩法协议不得丢条件。  
> 4. **可扩展**：结构必须继续支持「改角色设定」「加新 Prompt 块」而不必推翻整坨 system。

---

## 一、拆分 vs 瘦身：分别是什么

| | **拆分** | **瘦身** |
|--|--|--|
| 干什么 | 把消息**搬家**：固定人设一条、本轮状态另一条 | 把字数**变少**：去重、压缩表述、场景门控（有场景才注入） |
| 改不改「内容含义」 | 理想情况：**不改** | 只有「信息等价」才允许；删戏规 = 违规 |
| 主要赚什么 | **多轮缓存**（人设不必每轮重算） | **每轮少读 token**（单轮也更快） |
| 和角色的关系 | 几乎无关（结构手术） | **高风险**——一刀砍错就伤人设/玩法 |

你更关心的是 **瘦身**；下面以瘦身为主，拆分只作对照。

---

## 二、好处与风险（对照用）

### 2.1 拆分（静态 / 动态拆 message）

**好处**
- 人设+规则固定在 `messages[0]`，多轮只变后面的「世界快照」→ KV 前缀可复用（我们实测：同 system 第二轮约 **10s→6.5s**）。
- **不删任何规矩**，最贴合硬规则 1～3。
- 以后加新 Prompt：往「静态层」或「动态层」插块即可，不必揉进巨石 system。

**风险**
- 实现若把动态块优先级写错，模型可能更听「后面的快照」、忽略前面人设（可用「快照不得覆盖声线」一句锁死）。
- 工程改动面：`promptAssembler` 消息结构；要回归换装/同屏/睡眠。

**结论**：拆分是**低风险加速**；与「一比一」兼容，建议作为结构底座。

---

### 2.2 瘦身（你要重点审的）

在硬规则下，合法瘦身**只有三类**：

| 类型 | 含义 | 是否一比一 | 例 |
|--|--|--|--|
| **A. 去重** | 同一条规矩写了两遍→留一份权威稿 | ✅ | 指挥官羁绊写了两次；换装说明重复段 |
| **B. 压缩表述** | 字变少，条件一个不少 | ✅（需人工对表） | 长句改 bullet，不删条件 |
| **C. 场景门控** | 非场景不注入；**进入场景时注入全文与现网一致** | ✅ | 洗浴协议只在浴室出现 |

非法瘦身（**禁止**）：
- 删声线 / 正反例 / 禁止 / 好感区间 / 成人口径  
- 删玩法条件（「禁止同一轮既说去换又说已换好」等）  
- 「大概懂就行」式省略  
- 为本地方便改千问主路径默认行为（本地可另开等价压缩稿，但语义要对齐）

**好处（合法瘦身）**
- 去掉重复 token → prefill 下降（重复羁绊/换装段大约可省数百～上千字）。
- 门控后，非相关场景更干净，模型更少被无关细则带偏——**玩法条件在触发时仍完整**。
- 人设卡本身已经短，合法空间主要在**共享层重复**，不是砍 13 人个性。

**风险（即使合法也要防）**
- 「压缩表述」若漏条件 → 静默伤玩法（必须有对照表 + 回归清单）。
- 门控漏触发（人在浴室却没注入洗浴协议）→ 玩法失效。
- 去重时删错「权威稿」、留下弱表述。

## 三、Prompt 真实结构（先搞清「瘦哪里」）

每轮大致：

```
【共享·几乎所有人相同】
  指挥官羁绊 + 说话底线 + 成人硬规则
  换装 / 皮肤clip / 洗浴 / 深场字段 / JSON schema
  连续对话规则 + 深场加料（assembler 静态）
  动态：位置/好感/欲望/经济/事件/记忆…（每轮变，且有重复）

【每人不同·真正的「角色自己」】
  身份锁 + 档案 summary/恐惧/需要/秘密/关系笔记
  VOICE 声线 / 好感公式 / flavor / 正例 / 反例 / 禁止 / 成人
```

**关键事实**：  
13 人差异几乎全在 **VOICE + 档案**；体积大头是 **共享规则 + 动态重复**。  
所以「按角色瘦身」若去砍 VOICE/档案，必然违硬规则；合法瘦身主战场在**共享去重 / 门控 / 动态去重**。

导出体量（含本地适配头的 full）：每人大约 **7.2～7.4k 汉字**，彼此差距很小 → 证明大头是共享层。

### 每人「档案层」与「声线层」是否重复？

多数人存在 **轻度同义重复**（可信息等价合并，不可删）：

| 角色 | 重复点 | 一比一合并方式 |
|--|--|--|
| 澪 | `speechStyle`≈voice「关心=确认跟上」；forbid 再禁傲娇 | 保留 VOICE 正反例为权威；档案 speechStyle 缩成「同声线卡」指针式一句，或删档案句但**VOICE 全文保留** |
| 芹奈 | speechStyle 与 voice/forbid 三处反刻薄傲娇 | 同上：一处权威 + 档案不丢 summary/恐惧/秘密 |
| 玲/凛/朱里等 | speechStyle 与 voice 同向 | 可去重表述，**flavor/good/bad 必须留** |
| 全员 | `DIALOGUE_BASE_RULES` 已禁统一傲娇；各人 bad 又举自己的傲娇反例 | **两边都要留**：全局禁模板 + 个人反例是身份锚 |

**结论**：角色专属块合法瘦身空间极小；真正能瘦的是共享重复，不是「每个角色砍一段个性」。

## 五、共享层：一比一合法瘦身清单（主战场）

### 5.1 明确重复（去重 = 等价）

| 重复项 | 出现位置 | 一比一做法 | 伤角色？ | 伤玩法？ |
|--|--|--|--|--|
| 指挥官羁绊 | `DIALOGUE_BASE_RULES` 内嵌 + `contextParts` 再 `buildCommanderBondPromptBlock()` | 只保留一处权威（建议静态人设内一份；动态不再整段复读，或动态只补「在线/离线」一行） | 否 | 否 |
| 换装时序 | 底线里一段 + `skin_change` 长段 + 疑似重复的「世界同步·换装完成」段 | 合并为**一份**完整换装协议；删文字重复，条件全集保留 | 否 | 否（条件必须齐） |
| 好感数字 | deepField「好感 x/100」+ 后面「与指挥官的关系」再写一遍 | 动态只留一处 | 否 | 否 |
| 深场字段说明 | 人设末【深场字段】+ assembler `jsonProtocol` | 只留一处 | 否 | 否 |
| 嘴腿/地点 | 底线【嘴腿同步】+ 动态位置/外观锁 | 底线留原则；动态留「此刻值」——不删原则 | 否 | 否 |

### 5.2 场景门控（触发时全文 = 现网）

| 块 | 门控条件 | 一比一含义 |
|--|--|--|
| 洗浴 `bath_intimate_consent` 长说明 | `bathe` / 浴室 | 不在浴室：不注入；在浴室：与现网同文 |
| 睡眠立绘说明 | 睡眠系统中 | 同上 |
| 小黑屋/调教 | 进行中 / 刚离开 / 威胁检测 | 已基本门控，保持 |
| 营地经济长说明 | 话含买送吃修 / 有 pending offer / 在商店等 | 触发时注入与现网同文 |
| 同屏硬锁 | 同屏事件 | 已有，保持 |

门控**不是删玩法**，是「用不到时不朗读」；扩展新玩法时按同样模式加门控块即可。

### 5.3 禁止动的玩法协议（可压缩字句，不可少条件）

- 换装：先答应→旧衣说话→完成后再按新衣；禁同轮已换好；pifu03 仅洗浴；pifu05 情趣意图；出征默认装甲  
- 嘴腿同步 / desire_next 不切景  
- bath_intimate_consent 真假与脱巾立绘  
- JSON 必填：emotion / dialogue / inner_thought / action / …  
- end_conversation / want_continue 互斥与收束  
- 人生时间线 / 目标：有注入则不得装无记忆  

### 5.4 动态层（加速相关，仍要一比一）

| 项 | 建议 | 说明 |
|--|--|--|
| deepField 长短版 | 短版若启用，必须覆盖长版**全部玩法相关字段语义**；否则禁用短版 | 当前代码里有 `false ? 短 : 长`，短版更激进——**未证明一比一前不要开** |
| 名册/闲聊种子 | 可门控，不可删「有同伴关系时的关系印象」所需信息 | 关系玩法 |
| 记忆召回条数 | 下调条数 ≠ 删规则；但回忆题会变钝 → **算体验变化，不算一比一**，需你另批 | 标成可选，默认不动 |

## 六、可扩展架构（方便以后改设定 / 加 Prompt）

在硬规则下，推荐分层（可先拆分落地，再去做重）：

```
L0  协议锁（本地 Fable / 或千问无）     ← 旁路专用，可加，不替代声线
L1  角色身份卡（VOICE + 档案事实）       ← 改设定只改这里；禁止为速度砍
L2  全员玩法宪法（羁绊/底线/成人/换装/JSON）← 权威一份；去重后只留这里
L3  场景门控包（洗浴/睡眠/小黑屋/经济/同屏）← 新玩法 = 新包，触发注入
L4  本轮世界快照（地点/好感/外观/欲望…） ← 每轮变；与 L1/L2 拆 message
L5  本轮回答锁                           ← 接戏
```

- **改角色设定**：只动 L1（+ 可选 L3 角色专属门控）。  
- **加新 Prompt**：新块进 L2（全局）或 L3（场景）或 L0（本地协议），不要糊进 L1。  
- **瘦身**：优先 L2/L4 去重与 L3 门控；L1 默认不动。

---

## 七、推荐实施顺序（仍等你勾选）

1. **先拆分（L1+L2 固定 / L4 动态）** — 不删语义，收益已验证。  
2. **再共享去重（§5.1）** — 真正的一比一瘦身。  
3. **再场景门控（§5.2）** — 触发时同文。  
4. **不做**：砍 VOICE/正反例、开未证明等价的 deepField 短版、降记忆条数（除非你另批）。
